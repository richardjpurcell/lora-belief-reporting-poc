# Run 035 twelve-transmitter schedule prep

## Purpose

Run 035 prepares a twelve-transmitter scheduled replay bridge following the successful Run 034 ten-transmitter SD-backed scheduled physical replay.

This is a schedule-preparation milestone only. It does not modify firmware, copy schedules to SD cards, compute the final phase plan, flash transmitters, collect receiver logs, or make physical replay claims.

The purpose is to create the Run 035 manifest-bound schedule artifacts that will be used by the next deterministic phase-aware planning milestone.

## Relation to previous milestones

Run 035 follows:

- `v5.11-run034-ten-transmitter-synthesis`
- `v5.12-run035-twelve-transmitter-cautious-bridge-design`

The v5.12 design milestone established that twelve-transmitter work must remain staged.

This milestone deliberately stops before deterministic startup offset planning. Phase planning is deferred to:

- `v5.14-run035-twelve-transmitter-phase-plan`

## Schedule-prep script

Run 035 schedule artifacts are generated by:

- `scripts/prepare_run035_twelve_tx_schedules.py`

The script extends the Run 034 schedule-preparation pattern to twelve transmitters.

It uses the Run 034 TXA fixed-all schedule as the 64-row source schedule:

- `traces/run034_reporting_txa_fixed_all_schedule.csv`

- `traces/run035_twelve_tx_base_schedule.csv`

- `traces/run035_reporting_reporting_schedule_manifest.json`

## Twelve-transmitter ladder

Run 035 keeps the Run 034 A-J transmitter set and adds TXK/N151 and TXL/N166.

| TX | Node | Role | Scheduled SEND rows |
| --- | --- | --- | ---: |
| TXA | N01 | fixed-all anchor | 64/64 |
| TXB | N16 | medium threshold scheduled skipping | 32/64 |
| TXC | N31 | strict threshold scheduled skipping | 16/64 |
| TXD | N46 | very-strict threshold scheduled skipping | 8/64 |
| TXE | N61 | medium threshold scheduled skipping | 32/64 |
| TXF | N76 | strict threshold scheduled skipping | 16/64 |
| TXG | N91 | very-strict threshold scheduled skipping | 8/64 |
| TXH | N106 | ultra-strict threshold scheduled skipping | 4/64 |
| TXI | N121 | strict threshold scheduled skipping | 16/64 |
| TXJ | N136 | very-strict threshold scheduled skipping | 8/64 |
| TXK | N151 | medium threshold scheduled skipping | 32/64 |
| TXL | N166 | ultra-strict threshold scheduled skipping | 4/64 |

The two new transmitter roles are:

- TXK/N151: medium threshold scheduled skipping, 32/64 SEND rows
- TXL/N166: ultra-strict threshold scheduled skipping, 4/64 SEND rows

TXK adds a third medium-rate participant.

TXL adds a second ultra-sparse participant.

## Phase planning deferred

The manifest intentionally leaves startup offsets unset:

- `startup_offset_ms: null`
- `startup_offset_status: deferred to v5.14-run035-twelve-transmitter-phase-plan`

This is deliberate.

The next milestone should compute a phase-aware startup plan using the generated Run 035 schedules. It should check:

- exact same-ms scheduled SEND coincidences;
- near scheduled SEND coincidences within at least 150 ms;
- pairwise repeated overlap patterns;
- whether sparse transmitters have all scheduled SEND rows aligned with denser transmitters;
- whether TXH and TXL, the two ultra-strict transmitters, have distinguishable scheduled SEND opportunities;
- whether candidate offsets introduce repeated coincidences involving TXK or TXL.

The phase-plan milestone should produce preserved exact/near coincidence artifacts before firmware or physical preparation.

This milestone does not create TXK or TXL firmware.

| TX | Firmware directory | Sketch file |
| --- | --- | --- |

Later physical preparation will also require two additional SD cards. Those cards should be renamed from the default `NO NAME` volume label to appropriate TX-specific labels before use.

## Interpretation boundaries

This milestone does not establish:

- twelve-transmitter physical replay success;
- exact transmitted-packet counts;
- confirmed RF collision mechanisms;
- absence of collisions;
- synchronized latency;
- LoRaWAN behavior;
- energy savings;
- airtime optimization;
- live-controller behavior;
- arbitrary-layout twelve-node behavior;
- operational wildfire deployment behavior.

This milestone supports:

- a manifest-bound twelve-transmitter schedule set;
- expected scheduled ratio definitions for twelve transmitters;
- SD schedule inputs for later physical preparation;
- a clean handoff to deterministic phase-aware startup planning.
