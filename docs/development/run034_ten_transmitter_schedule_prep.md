# Run 034 ten-transmitter schedule prep

## Purpose

Run 034 prepares a ten-transmitter scheduled replay bridge between the validated Run 033 eight-transmitter replay and a future twelve-transmitter target.

This is a schedule-preparation milestone only. It does not modify firmware, copy schedules to SD cards, compute the final phase plan, flash transmitters, collect receiver logs, or make physical replay claims.

The purpose is to create the Run 034 manifest-bound schedule artifacts that will be used by the next phase-aware planning milestone.

## Relation to previous milestones

Run 034 follows:

- `v5.3-run033-eight-transmitter-physical-replay`
- `v5.4-run033-eight-transmitter-synthesis`
- `v5.5-phase-aware-replay-method-freeze`
- `v5.6-run034-ten-transmitter-bridge-design`

The v5.5 method freeze established that future larger physical replays should compute exact and near scheduled SEND coincidences before physical preparation.

This milestone deliberately stops before that step. Phase planning is deferred to:

- `v5.8-run034-ten-transmitter-phase-plan`

## Schedule-prep script

Run 034 schedule artifacts are generated by:

- `scripts/prepare_run034_ten_tx_schedules.py`

The script extends the Run 033 schedule-preparation pattern to ten transmitters.

It uses the Run 033 TXA fixed-all schedule as the 64-row source schedule:

- `traces/run033_reporting_txa_fixed_all_schedule.csv`

It writes a Run 034 base schedule copy:

- `traces/run034_ten_tx_base_schedule.csv`

It writes the Run 034 manifest:

- `traces/run034_reporting_reporting_schedule_manifest.json`

## Validation performed

The generated schedules were checked for:

- 64 rows per schedule
- expected SEND row count per transmitter
- expected SKIP row count per transmitter
- SD schedule row counts matching reporting schedule row counts
- manifest transmitter count of 10
- expected scheduled ratios relative to TXA

The schedule validation passed.

## Phase planning deferred

The manifest intentionally leaves startup offsets unset:

- `startup_offset_ms: null`
- `startup_offset_status: deferred to Run 034 phase-plan milestone`

This is deliberate.

The next milestone should compute a phase-aware startup plan using the generated Run 034 schedules. It should check:

- exact same-ms scheduled SEND coincidences
- near scheduled SEND coincidences
- pairwise repeated overlap patterns
- whether sparse transmitters have all scheduled SEND rows aligned with denser transmitters

The phase-plan milestone should produce a preserved artifact before firmware or physical preparation.

## Interpretation boundaries

This milestone does not establish:

- ten-transmitter physical replay success
- exact transmitted-packet counts
- confirmed RF collision mechanisms
- absence of collisions
- synchronized latency
- LoRaWAN behavior
- energy savings
- airtime optimization
- live-controller behavior
- twelve-transmitter behavior
- operational wildfire deployment behavior

This milestone supports:

- a manifest-bound ten-transmitter schedule set
- expected scheduled ratio definitions for ten transmitters
- SD schedule inputs for later physical preparation
- a clean handoff to phase-aware startup planning
