## One-card-at-a-time workflow

Run 034 showed that one-card-at-a-time SD preparation is the safer current bench workflow.

The intended workflow for each card is:

1. Mount one SD card.
2. Confirm or set the card label.
3. Run the copy helper for the matching TX ID.
4. Confirm that `schedule.csv` exists on the mounted card.
5. Eject the card cleanly.
6. Install it in the matching transmitter.
7. Repeat for the next transmitter.

This avoids ambiguity when only one card can be mounted at a time.

## Manual bench checklist

Before attempting the physical replay:

1. Open each firmware sketch in Arduino IDE or the selected flashing workflow.
2. Confirm `RUN_ID = "R35"`.
3. Confirm `TX_ID` and `NODE_ID` match the transmitter label.
4. Confirm `STARTUP_OFFSET_MS` matches the table in this note.
5. Flash all twelve transmitters.
6. Mount each SD card one at a time.
7. Confirm the volume label is `LORA_TXA` through `LORA_TXL`.
8. For TXK and TXL, rename new cards from `NO NAME` to `LORA_TXK` and `LORA_TXL`.
9. Remove any old `schedule.csv` or `SCHEDULE.CSV`.
10. Copy the matching Run 035 SD schedule as `schedule.csv`.
11. Eject cards cleanly.
12. Install each card in the matching transmitter.
13. Prepare the receiver log capture before powering the transmitters.
14. Start the physical replay using the deterministic startup-offset plan preserved in the firmware.

## Physical replay handoff

The physical replay milestone should collect the receiver-side log and then analyze it against:

- the Run 035 manifest;
- the assigned startup offsets;
- the expected scheduled ratios;
- the twelve expected transmitter identities;
- the reject/malformed packet file generated by the parser.

The replay should be interpreted manifest-relatively.

Receiver-side packet counts should not be treated as exact transmitted-packet counts.
